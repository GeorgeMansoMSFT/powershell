Recommended next steps

1. Address hard blockers

Hard blockers are objects that will prevent domain removal until cleared: users, groups, app registration identifier URIs, managed identities, mailboxes, distribution lists, mail-enabled security groups, and accepted domains. For each finding, decide:

  • Migrate — preserve in destination tenant
  • Recreate — rebuild in destination, retire here
  • Retire — no longer needed

Build a remediation plan with an owner and due date for each item.

2. Convert UPNs to .onmicrosoft.com

Per Microsoft's UPN change guidance, change all on-prem AD userPrincipalName values from @contoso.com to @<tenant>.onmicrosoft.com, then trigger an Entra Connect delta sync. Pilot a small group first — this is a user-facing change. Sign-in with the old UPN stops working as soon as sync propagates, and Outlook/Teams clients will require reauthentication.

3. Clear Exchange-mastered objects

Mail-enabled security groups, distribution lists, and lingering proxyAddresses must be cleaned up in the Exchange Admin Center — these don't surface in Entra Connect or Graph queries directly.

4. Address soft blockers before cutover

Soft blockers (service principal reply URLs, Conditional Access policy references, Azure resource custom domain bindings) won't prevent domain removal but will cause downstream breakage if left alone. Update reply URLs and notification emails on service principals, edit CA policies that reference the domain, and reconfigure Azure resource custom domain bindings before cutover.

5. Address app-level UPN dependencies

Review the sign-in activity output (09-signins-by-app.csv) — the top apps by sign-in volume are your highest-priority validation targets post-UPN-change. Apps with hardcoded @contoso.com identifiers will need configuration updates.

6. Verify federation status

If 08-federation-config.csv shows AuthenticationType = Federated, you must convert the domain to Managed authentication (or remove the federation configuration) before the domain can be released. Most tenants are already Managed; this step is only relevant for federated configurations.
